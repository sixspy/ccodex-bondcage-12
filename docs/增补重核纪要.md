# 增补重核纪要（2026-11-22 当日锁死）

> 适用产品：保证金笼（`11-bondcage`）
> 触发场景：同笼增补抬额（扩额）后，增补前核验结论不得继续作为出金/罚没依据。
> 锁死方式：本文件内容摘要写入 `docs/增补重核纪要.sha256`；摘要不一致即视为纪要被动过，重核闸门必须拒绝写入。

## 一、事故口径

增补抬额后，旧核验结论仍算数、柜员可直接解笼，等于没人复核新金额。该状态视为假绿事故，必须由增补与重核硬衔接消除。

## 二、唯一正确性口径：甲路径

本仓只采用 **甲路径**，不得与乙路径混用。

甲路径定义：

1. 增补提交、扩额、作废旧核验、笼改「待重核」态、写审计，必须在同一事务内完成。
2. 任一环节失败，增补与作废同时回滚；不得出现「钱进来了、旧结论还在」或「旧结论作废了、钱没进来」。
3. 作废只针对当前笼代仍有效的旧核验结论；旧结论保留原行，写 `voided_at` / `voided_by` / `void_reason`，禁止物理删除。
4. 待重核态下，解笼拨付与罚没口一律关闭；必须重新核验并写入新结论后才可出金/罚没。
5. 新结论写入后，笼状态回到「核验通过」或「核验违约」，旧结论保持作废痕。

乙路径（影子复检单）不采用；任何请求若声明乙路径、影子复检、或除「同笼扩代」以外的增补模式，记「重核偏航」并拒绝写入。

## 三、拒绝与留痕

- 待重核笼上的解笼、罚没写入一律 409 拒绝。
- 使用已作废旧结论尝试出金/罚没，一律 409 拒绝，并记审计动作 `recheck_deviation`（重核偏航）。
- 增补请求偏离本纪要（路径/模式不符），同样记 `recheck_deviation` 并拒绝。
- 两人同时争用同一增补后笼的出金口，必须抢 `cage:{id}` 笼锁；后到者只留 `contention_log` 争用痕，不写业务。

## 四、五页同源

增补页、核验页、解笼页、罚没页、审计页的账实必须同源读取 `/api/recheck/board`：

- 同一笼状态（`待重核` / `核验通过` / `核验违约`）
- 同一旧核验作废痕
- 同一增补 job 与审计偏航记录
- 同一出金/罚没闸门开关

禁止任一页只改提醒文案而闸门未落库。

## 五、验收顺序

1. 先落事故夹具：增补后旧结论仍可解笼，失败测见红。
2. 再落双人同出金争用失败测见红。
3. 两条失败测见红后，才允许改增补 / 核验 / 解笼 / 罚没服务与增补页、核验页。
4. 改完必须满足：扩额后必须重核才能出金。
